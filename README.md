# 源集 YUANJI · 专业 B2B 批发采购前端原型

> 参数优先、视觉克制的专业采购界面 —— 面向中小批发采购者的高保真静态原型。
>
> 与设计规范导航页、四个业务页面、产品需求文档（PRD）和设计稿一并归档于本仓库。

---

## 一、项目简介

B2B 批发采购的核心任务是「在可信供给中快速比价并下单」。采购者的决策高度依赖**起批量（MOQ）、阶梯报价、交期、供应商资质**等专业参数，而主流平台（如 1688）以橙红营销色、九宫格楼层和「逛」式信息流为主，营销氛围浓、比价效率低。

「源集 YUANJI」是面向这一痛点的前端原型：以「专业采购工作台」的气质，把 B2B 关键决策参数前置，直接服务 **找货 → 比货 → 决策 → 采购管理** 闭环。

| 维度 | 说明 |
|------|------|
| 一句话定位 | 面向中小批发采购者、参数透明且视觉克制的专业采购前端界面 |
| 本期形态 | 高保真**静态页面**，数据为前端 mock，不接真实交易后端 |
| 差异化锚点 | 冷静专业色系、参数优先信息流、任务导向交互 |
| 视觉风格 | Swiss / 蓝白（Yves Klein Blue）+ Blueprint 工程参数刻度 |

> 详细的产品定义、需求编号（FR-xx）、验收标准、状态机与指标口径见 [`B2B批发采购平台-四页面PRD.md`](./B2B批发采购平台-四页面PRD.md)。

## 二、快速开始

纯静态站点，**无需构建、无需安装依赖**。两种方式任选：

**方式一：直接打开**
浏览器打开 [`index.html`](./index.html) 进入设计规范与页面导航，点击卡片跳转各页面。

**方式二：本地起服务**（推荐，避免个别浏览器对 `file://` 的限制）

```bash
# Python 3
python -m http.server 8080
# 或 Node.js
npx serve .
```

访问 `http://localhost:8080`。

**页面直达**

| 文件 | 页面 | 作用 |
|------|------|------|
| `index.html` | 设计规范与原型导航 | 入口，汇总色板/组件/页面跳转 |
| `01-home.html` | 首页 · 发现导购 | 场景找货、采购工具、采购看板、推荐商品流 |
| `02-listing.html` | 搜索/分类结果页 · 比货 | 多维筛选、排序、网格/对比视图切换、询价篮 |
| `03-detail.html` | 商品详情页 · 决策 | 主图、SKU、阶梯报价表、供应商档案、询盘/加车 |
| `04-workbench.html` | 采购工作台 · 管理 | 采购车、询盘管理、订单履约、收藏、数据小结 |

## 四、页面与功能

### 4.1 首页（发现 / 导购）

建立专业信任 + 分发流量到找货链路。

- **全局搜索**：关键词搜索跳转结果页并携带 `?kw=` 参数；图片找货入口（本期模拟）
- **采购身份筛选**：源头工厂 / 一件代发 / 进口快捷切换
- **一级类目导航**：横向类目，支持二级展开（不超过 2 层）
- **场景化频道入口**：按采购场景聚合的频道卡片（非营销楼层）
- **采购看板**：今日报价 / 新品 / 产地行情信息块，含标题与更新时间
- **推荐商品流**：参数优先的商品卡片网格，支持换一批/加载更多

> 边界：不做营销 Banner 轮播、不做倒计时促销，避免视觉雷同。

### 4.2 搜索 / 分类结果页（比货页）

差异化核心承载页。

- **多维筛选**：价格区间、MOQ、交期、产地、认证、发货地，条件可叠加
- **筛选回显与清除**：已选条件回显，单项删除与一键清空
- **视图切换**：网格视图 / 对比列表视图，切换保留筛选、排序与勾选态
- **排序**：综合 / 价格 / 成交量 / 交期
- **对比勾选**：最多 4 件，横向对齐主图、阶梯价、MOQ、交期、成交量、供应商、资质
- **常驻询价篮**：跨页累加（localStorage），角标实时更新
- **结果三态**：空结果 / 加载中 / 无更多，均有引导，禁止空白页

### 4.3 商品详情页（决策页）

用参数与资质消除采购疑虑。以「304 不锈钢保温杯 定制logo」为示例商品。

- **主图区**：主图 + 多图缩略切换 + 视频占位
- **SKU 选择**：颜色/容量规格联动价格与库存，缺货组合置灰
- **阶梯报价表**：数量分档单价，命中档位高亮并计算预估金额
- **供应商档案卡**：资质证照、工厂实拍、成立时间、回头率，缺失项标注「暂无」
- **服务与保障**：发货时效、退换政策、定制能力（每项有明确文案）
- **询盘 / 加车**：发起询盘、按 SKU 与数量加入采购车，均有反馈提示
- **同款比价与关联推荐**：列出其他供应商报价及其 MOQ

### 4.4 采购工作台（管理页）

聚合采购车、询盘、订单，管住采购全流程。Tab 结构：

- **采购车**：按供应商分组、各组小计、批量改规格/数量/删除/移入询价篮
- **询盘管理**：状态（待回复 / 已回复 / 已关闭）与时间线
- **订单履约**：待确认 → 待发货 → 已发货 → 已签收；异常分支待确认 → 已取消
- **收藏与常用供应商**：收藏分组、最近采购供应商入口
- **采购数据小结**：本月采购额、节支、供应商占比，含口径与统计周期

## 五、技术实现

| 项 | 实现 |
|----|------|
| 技术栈 | 原生 HTML + CSS + JavaScript，零依赖、零构建 |
| 设计令牌 | `tokens.css` 用 CSS 变量统一色板、字体、圆角、间距、阴影 |
| 图标 | `icons.js` 内联 SVG sprite，`<use href="#i-xxx">` 复用，Swiss 线性风格 |
| 商品图 | `product-art.js` 按品类（保温杯/快递袋/耳机/展示架/分装瓶/置物架）程序化生成工程线稿，含尺寸标注，零外链、去占位符 |
| 跨页状态 | `localStorage` 键 `yj_inquiry`（询价篮）、`yj_cart`（采购车） |
| 交互封装 | `app.js` 暴露 `window.YJ`：`addInquiry/removeInquiry/clearInquiry/addCart/read/write/toast/refreshBadges` |
| 状态反馈 | Toast 提示、导航角标（询价篮/采购车）实时联动 |
| 安全 | `esc()` 对渲染文本做 HTML 转义，防注入 |
| 响应式 | 桌面 1280px 栅格基准，窄屏网格降列且核心参数（价格/MOQ）不隐藏 |
| 兼容性 | 现代浏览器（Chrome / Edge） |

**交互状态流转**

- 询盘：`待回复 → 已回复 → 已关闭`（单向，禁止从已关闭回跳，防重放）
- 订单：`待确认 → 待发货 → 已发货 → 已签收`；异常分支 `待确认 → 已取消`
- SKU：未选择 → 部分选择 → 已选齐（可下单）/ 缺货（置灰不可下单）

**本期边界（明确不做）**

真实下单与支付、账号与登录态、真实消息推送、后台管理端、移动端原生 App、后端接口对接。所有按钮动作均为前端模拟，不产生真实资金/账号副作用。

## 六、设计系统

| 维度 | 规范 |
|------|------|
| 锚点 | Swiss —— 纯白 + Yves Klein Blue + 无衬线 + 可见网格 |
| 记忆点 | Blueprint 工程参数刻度：价格梯度条 + 24px 工程网格 + Swiss 编号系统 |
| 主色 | `#002fa7`（Yves Klein Blue），深蓝 `#001a57` / `#00247d` |
| 强调色 | 单一青蓝，无大面积红黄促销色、无高饱和渐变/彩虹色 |
| 圆角 | 近乎直角（`--r-xs: 0px`） |
| 阴影 | 极少，靠 1px 细线划分区域 |
| 字体 | 单一无衬线家族（Helvetica Neue / Arial / 苹方 / 微软雅黑） |
| 信息密度 | 商品卡首屏可见有效决策字段 ≥ 4 个（价格/MOQ/交期/资质） |

**差异化品卡片字段（9 项）**：主图、标题、阶梯价、MOQ、30 天成交量、供应商+产地、服务保障标签、规格/货号、供应商资质标。决策带（阶梯价/MOQ/交期）前置，营销类信息弱化于底部。

完整视觉规范见导航页 [`index.html`](./index.html) 与设计稿 [`design-images/00-design-spec.png`](./design-images/00-design-spec.png)。

## 七、名词解释

| 术语 | 含义 |
|------|------|
| MOQ | Minimum Order Quantity，起批量，单笔订单最小采购数量 |
| 阶梯报价 | 按采购数量分档的价格表，量越大单价越低 |
| 交期 | 从下单确认到发货的承诺时长 |
| 询价篮 | 跨页面累加候选商品的临时清单，可批量发起询盘 |
| 询盘 | 采购者向供应商发起的价格/交期/定制咨询 |
| 一件代发 | 供应商代发货、采购者无需囤货的履约方式 |
| 源头工厂 | 具备生产资质、非纯贸易转售的供应商身份标签 |

## 八、演进路径

- **本期**：静态页面 + mock 数据，验证信息架构与视觉。
- **下一期**（触发：视觉与流程评审通过）：接入商品/供应商真实读接口，保留前端参数口径。
- **后续**（触发：进入真实交易开发）：补齐账号鉴权、下单、支付，以及资金安全三件套（幂等 + 对账 + 资损监控）。
