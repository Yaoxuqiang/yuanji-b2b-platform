# 源集 YUANJI · 专业 B2B 批发采购前端

> 参数优先、视觉克制的专业采购界面 —— 面向中小批发采购者的高保真静态站点。
>
> 四个业务页面已按 v2 设计稿（墨绿 / 灰白）重做；商品、报价、采购车与询盘均为本地模拟数据，不接真实交易后端。

---

## 一、项目简介

B2B 批发采购的核心任务是「在可信供给中快速比价并下单」。采购者的决策高度依赖**起批量（MOQ）、阶梯报价、交期、供应商资质**等专业参数，而主流平台多以橙红营销色和「逛」式信息流为主，营销氛围浓、比价效率低。

「源集 YUANJI」把 B2B 关键决策参数前置，直接服务 **找货 → 比货 → 决策 → 采购管理** 闭环。

| 维度 | 说明 |
|------|------|
| 一句话定位 | 面向中小批发采购者、参数透明且视觉克制的专业采购界面 |
| 本期形态 | 高保真静态页面，原生 HTML/CSS/JS，零依赖、零构建 |
| 数据形态 | 内置商品目录与本地持久化演示状态，无后端请求 |
| 差异化锚点 | 墨绿专业色系、参数优先信息流、常驻询价篮、按采购量试算 |
| 视觉基准 | v2 设计稿：[首页](./design-images/v2/01-home.png) · [结果页](./design-images/v2/02-listing.png) · [详情页](./design-images/v2/03-detail.png) · [工作台](./design-images/v2/04-workbench.png) |

> 产品定义、需求编号（FR-xx）、验收标准、状态机与指标口径见 [`B2B批发采购平台-四页面PRD.md`](./B2B批发采购平台-四页面PRD.md)。PRD 为 v1.0 产品口径，视觉以 v2 设计稿为准。

## 二、快速开始

纯静态站点，**无需安装依赖**。

**方式一：直接打开**

浏览器打开 [`index.html`](./index.html)，会自动进入采购首页；四个页面之间可直接相对跳转。

**方式二：本地起服务（推荐）**

跨页保留采购车、询价篮依赖同源 `localStorage`，个别浏览器对 `file://` 的存储行为不一致，建议：

```bash
# Python 3
python -m http.server 8080
# 或 Node.js
npx serve .
```

访问 `http://localhost:8080`。

**页面直达**

| 文件 | 页面 | 内容 |
|------|------|------|
| `index.html` | 入口 | 自动跳转 `01-home.html` |
| `01-home.html` | 首页 · 发现导购 | 类目与采购身份、四个采购场景、采购看板、参数优先商品卡 |
| `02-listing.html` | 搜索/分类结果页 · 比货 | 六维筛选、排序分页、网格/对比列表、按采购量试算、询价篮 |
| `03-detail.html` | 商品详情页 · 决策 | 主图与细节图、三档报价、SKU 库存、采购数量与预估金额、供应商档案 |
| `04-workbench.html` | 采购工作台 · 管理 | 采购车分组与批量操作、询盘、订单、收藏、数据小结 |

示例商品直达：[304 不锈钢保温杯](03-detail.html?id=p1)。

## 四、页面与功能

### 4.1 首页（发现 / 导购）

- **统一页头**：搜索、图片找货（仅本地选图演示）、采购车/询价篮角标、登录占位
- **类目与身份**：一级类目横向导航与二级展开；源头工厂 / 一件代发 / 进口快捷入口
- **场景频道**：小单试采、品牌定制、现货快发、一件代发，点击带筛选条件进入结果页
- **采购看板**：今日报价、新品上架、产地行情，均含更新时间并可跳转
- **推荐商品流**：图左价右的参数优先卡片，支持换一批与加载更多

### 4.2 搜索 / 分类结果页（比货页）

- **筛选**：价格区间、起批量、交期、产地、认证、发货地，条件可叠加
- **已选条件**：单项移除与一键清空，条件会回写筛选表单
- **排序与分页**：综合、价格、成交量、交期；分页按当前 mock 结果真实计算
- **双视图**：网格 / 对比列表，切换保留筛选、排序与勾选态
- **对比勾选**：最多 4 件；“仅看已选”只隐藏非勾选行，不丢失选择
- **按采购量试算**（默认收起）：对已勾选商品按同一采购量复用阶梯计价，未达 MOQ 或超库存明确提示
- **常驻询价篮**：列表内直接加入，右侧篮子可移除，跨页保留

### 4.3 商品详情页（决策页）

- **主图与细节图**：主图、内胆/杯口/杯盖细节、视频占位
- **阶梯报价**：50–499 / 500–1999 / ≥2000 三档，按当前采购量高亮“当前档”
- **规格与库存**：颜色、容量联动价格与库存；缺货规格禁用
- **采购数量**：受起批量与库存约束，实时显示预估金额
- **加入采购车 / 发起询盘**：按 SKU 与数量加入；询盘可携带留言进入询价篮
- **供应商档案**：产地、资质（示例）、成立年份、回头率，缺失项标注“暂无”
- **同款比价与关联商品**：给出其他供应商报价、MOQ 与跳转

示例：500 件雾松绿/500mL 命中 ¥12.50 档，预估 **¥6,250.00**。

### 4.4 采购工作台（管理页）

- **五个页签**：采购车、询盘、订单、收藏与供应商、数据小结
- **采购车**：按供应商分组并小计；全选/分组选择；行内改数量；批量改规格/数量、删除、移入询价篮
- **采购摘要**：已选项数、供应商数、预估合计（默认示例为 **¥9,610.00**）
- **待跟进**：最近待回复/已回复询盘，可跳转查看
- **询盘**：从询价篮勾选提交模拟询盘，生成“待回复”记录；关闭后为终态
- **订单**：四种履约状态筛选，金额由同一计价函数计算
- **数据小结**：采购额、节支、头部供应商占比（附口径）与近 6 个月采购额条形图

## 五、技术实现

| 项 | 实现 |
|----|------|
| 技术栈 | 原生 HTML5 + CSS + JavaScript（经典脚本，无模块、无第三方库） |
| 架构 | `app.js` 负责目录、状态、计价、公共组件；`pages.js` 按 `body[data-page]` 初始化页面 |
| 共享 API | `window.YJ`：`catalog / product / skuFor / quote / money / state / save / addCart / addBasket / submitBasket / dialog / toast` |
| 计价 | 全部使用**整数分**；SKU 加价与阶梯价由同一 `quote()` 计算，越界返回 `null` |
| 状态持久化 | `localStorage` 键 `yj_demo_v2`，保存采购车、询价篮、询盘记录；读取时逐项校验商品、规格、数量 |
| 初始演示数据 | 采购车 2 项（保温杯 500 件、收纳盒 200 件）；询价篮 2 项；2 条询盘记录 |
| 去重与上限 | 采购车按“商品 + SKU”合并数量；询价篮按商品去重，上限 8 项 |
| 安全 | 用户留言与动态文本统一 `esc()` 转义；图片加载失败显示占位文案；无外链资源 |
| 可访问性 | 语义化表格/表单、可见焦点、`aria-pressed` / `aria-current` / `role=status`，宽表容器可键盘聚焦横滚 |
| 响应式 | 桌面 1536/1280 栅格基准；≤1100 / 820 / 560px 分级重排，价格与 MOQ 不隐藏，宽表局部滚动 |

**业务测试**

```bash
node assets/app.test.cjs
# 通过：阶梯价、SKU 库存、采购车、询价篮及本地存储。
```

覆盖 49/50/499/500/1999/2000 件阶梯边界、SKU 缺货与加价、500 件合计 ¥6,250、默认采购车合计 ¥9,610、重复加车合并、询价篮去重与 8 项上限、提交询盘后仅移除已提交项、损坏存储回退。

**本期边界**

真实下单与支付、账号鉴权、真实消息推送、后台管理端、后端接口均未实现；登录、图片识别、询盘回复、订单状态均为前端演示，不产生真实资金或账号副作用。

## 六、设计系统

| 维度 | 规范 |

## 七、名词解释

| 术语 | 含义 |
|------|------|
| MOQ | Minimum Order Quantity，起批量，单笔订单最小采购数量 |
| 阶梯报价 | 按采购数量分档的价格表，量越大单价越低 |
| 交期 | 从下单确认到发货的承诺时长 |
| 询价篮 | 跨页面累加候选商品的临时清单，可批量发起询盘 |
| 询盘 | 采购者向供应商发起的价格/交期/定制咨询 |
| 一件代发 | 供应商代发货、采购者无需囤货的履约方式 |
| 源头工厂 | 具备生产资质、非纯贸易转售的供应商身份标签 |

## 八、演进路径

- **本期**：静态页面 + 本地模拟数据，验证信息架构、视觉与采购操作闭环。
- **下一期**（触发：视觉与流程评审通过）：接入商品/供应商真实读接口，保留前端参数口径与计价边界。
- **后续**（触发：进入真实交易开发）：补齐账号鉴权、下单、支付，以及幂等、对账、资损监控。

> 本期为产品设计参考原型，供应商与资质均为示例。具体实施请结合合规与法务要求确认；内容为原创编写，不复制任何平台的专有文案、视觉与品牌元素。
